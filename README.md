# Muhammad Luqman — Developer OS

An English full-stack developer portfolio built with Next.js, TypeScript and React. Production domain: https://www.luqmandev.top.

## Run

```sh
npm ci
npm run dev
npm run typecheck
npm run build
npm start
```

## Experience

- Server-rendered portfolio, Work, About, Services, Guides and Contact pages.
- Three inspectable case studies, linked to the account's public repositories.
- A lightweight projected wireframe hero and a lazy-loaded WebGL skills universe.
- A pooled Canvas code-particle cursor for fine-pointer devices.
- Distinct project reveals, perspective interaction, architecture layers, a development pipeline and a Git-style build log.
- Responsive layouts, keyboard navigation, local Geist fonts, reduced-motion support, off-screen animation culling and optimised screenshots.
- SEO metadata, sitemap, robots rules, a custom favicon and security headers.

## Content integrity

The Circle case studies describe source code in `mluqman555/Circle-Arc-Net` and `mluqman555/Circle`. Their original product names and contributors remain visible through source and live links. No commercial outcomes, employment history, solo authorship, financial performance or fictional projects are asserted. The second project visual is a labelled architecture blueprint, not a fabricated application screenshot. The build log uses development stages rather than invented career dates.

## Contact

The contact email comes from the connected GitHub profile. The enquiry form validates input, prepares an email draft and offers a copy fallback. It does **not** claim server-side email delivery. Visitors complete sending through their own email app. Call enquiries use the same email route; no unconfigured calendar or invented LinkedIn link is published.

## Deployment

Vercel project `portfolio` is linked to this repository. Next.js framework, `npm ci` installation and `npm run build` are configured. Merges into `main` trigger production deployment. The apex `luqmandev.top` redirects to `www.luqmandev.top`.

## Performance

The application avoids loading Three.js or an animation framework; its small graphics modules use WebGL, Canvas, CSS and browser scheduling directly. The universe only loads near its section. All primary content is rendered before graphics are loaded. Actual field LCP, INP and CLS depend on production traffic and must not be represented as verified without real-user measurements.
